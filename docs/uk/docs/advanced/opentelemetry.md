# OpenTelemetry { #opentelemetry }

Коли ваш API працює, ви можете захотіти знати, скільки трафіку він отримує, які запити повільні та коли виникають помилки.

**Telemetry** - це дані про поведінку вашого застосунку, які допомагають відповісти на ці питання. Поширені типи:

- **Метрики**: вимірювання, які можна підсумовувати з часом, наприклад час відповіді та кількість запитів, що обробляються.
- **Трейси**: записи окремих запитів і операцій, виконаних для їх обробки. Кожна операція з виміряним часом називається **span**.
- **Логи**: записи подій із часовими мітками, наприклад запуск застосунку або збій операції.

[**OpenTelemetry**](https://opentelemetry.io/) - це набір стандартів та інструментів для збирання telemetry і надсилання її до сервісу моніторингу, де ви можете переглядати її на dashboards.

**FastAPI за замовчуванням підтримує OpenTelemetry** для трейсів, метрик і логів HTTP-запитів. WebSocket-з'єднання також надають трейси та логи. Щоб побачити ці дані, налаштуйте сервіс моніторингу для їх отримання.

## Інші сервіси моніторингу { #other-monitoring-services }

Щоб надсилати telemetry до іншого сервісу моніторингу, налаштуйте endpoint, який приймає **OTLP**, протокол OpenTelemetry для надсилання telemetry. Використовуйте базовий endpoint HTTP/protobuf сервісу.

Встановіть ці змінні оточення, замінивши URL прикладу на ваш endpoint:

```bash
export OTEL_SERVICE_NAME=my-api
export OTEL_EXPORTER_OTLP_ENDPOINT=https://collector.example.com
```

`OTEL_SERVICE_NAME` ідентифікує ваш застосунок у сервісі моніторингу. Endpoint - це базовий URL для отримання даних. Трейси надсилаються до `/v1/traces`, метрики - до `/v1/metrics`, а логи - до `/v1/logs` під цим URL.

Якщо ваш сервіс вимагає автентифікації, встановіть `OTEL_EXPORTER_OTLP_HEADERS` у заголовки, які він визначає, наприклад `api-key=YOUR_API_KEY`.

## Налаштуйте telemetry { #customize-telemetry }

### Налаштуйте providers та exporters { #configure-providers-and-exporters }

**Provider** надає об'єкти, які записують трейси, метрики або логи. Його конфігурація керує тим, як ці дані обробляються та експортуються.

Бібліотеки telemetry можуть налаштовувати глобальні providers OpenTelemetry. Налаштуйте бібліотеку до запуску застосунку, і FastAPI автоматично використовуватиме ці providers.

Коли endpoint OTLP встановлено в оточенні, FastAPI додає exporter для цього призначення до кожного увімкненого provider. Наявні exporters продовжують надсилати дані до своїх призначень.

Налаштуйте кожне призначення один раз. Якщо інша бібліотека вже обробляє призначення з оточення, вимкніть її експорт з оточення або вимкніть автоматичне налаштування FastAPI:

```python
app = FastAPI(telemetry={"auto_configure": False})
```

Ви також можете передати provider безпосередньо у словнику `telemetry`. Наприклад, цей provider використовує console exporter OpenTelemetry, щоб друкувати spans запитів у вашому терміналі:

{* ../../docs_src/opentelemetry/tutorial002_py310.py hl[2:8] *}

**Exporter** надсилає spans до їхнього призначення. `BatchSpanProcessor` групує spans і надсилає їх у фоновому режимі. Замініть console exporter на той, який надає ваша бібліотека моніторингу, щоб використовувати її призначення. Дивіться [посібник з інструментування Python від OpenTelemetry](https://opentelemetry.io/docs/languages/python/instrumentation/) для додаткових параметрів конфігурації.

Використовуйте `meter_provider` або `logger_provider` у тому самому словнику, щоб надати provider для метрик або логів. Застосунок або бібліотека, що створює provider, керує його вимкненням. FastAPI керує компонентами експорту, які він додає.

### Трасуйте операції запиту { #trace-request-operations }

За замовчуванням трейси запитів містять spans для вирішення залежностей, запуску вашої функції операції шляху, серіалізації відповіді та запуску кожного завдання у `BackgroundTasks` FastAPI. Ці spans використовують той самий provider і exporters.

Spans фонових завдань залишаються частиною трейсу запиту. Вони виконуються після завершення span HTTP-відповіді, тому не збільшують виміряний час відповіді.

### Трасуйте WebSocket-з'єднання { #trace-websocket-connections }

Кожне WebSocket-з'єднання має span, наприклад `WS /ws/{room}`, який охоплює handler і очищення залежностей. Він використовує ті самі providers і налаштування, включно з `operation_spans` для вирішення залежностей і виконання endpoint.

Метрики HTTP-запитів охоплюють лише HTTP-запити. Звичайні від'єднання WebSocket з кодами `1000` або `1001` не створюють логів помилок.

### Перевірте помилки { #inspect-errors }

FastAPI записує необроблені винятки як логи OpenTelemetry, пов'язані з трейсом запиту або з'єднання. Логи помилок записуються навіть тоді, коли трейс не семплюється.

Логи винятків містять тип винятку, повідомлення та stack trace. Повідомлення та stack traces можуть містити чутливу інформацію. Використовуйте log processors вашого provider, щоб відфільтрувати або замаскувати їх, або встановіть `logs` у `False`, щоб вимкнути ці логи.

FastAPI також записує збої валідації запитів як warning logs з маршрутом і кількістю помилок. Ці логи не містять недійсних вхідних даних.

## Виберіть, що записувати { #choose-what-to-record }

Словник `telemetry` також приймає такі налаштування:

| Налаштування | Призначення | За замовчуванням |
| --- | --- | --- |
| `tracing` | Записувати spans HTTP-запитів і WebSocket-з'єднань | `True` |
| `metrics` | Записувати метрики HTTP-запитів | `True` |
| `logs` | Записувати збої валідації та необроблені винятки | `True` |
| `operation_spans` | Додавати spans для операцій запиту | `True` |
| `exclude` | Пропускати запити, коли функція, що отримує ASGI scope, повертає `True` | `None` |
| `auto_configure` | Додавати exporters для endpoints, встановлених у змінних оточення | `True` |

Наприклад, щоб збирати метрики, виключаючи перевірки працездатності:

```python
from fastapi import FastAPI

app = FastAPI(
    telemetry={
        "tracing": False,
        "exclude": lambda scope: scope["path"] == "/health",
    }
)
```

Встановіть `auto_configure` у `False`, коли ваш застосунок сам обробляє налаштування provider, наприклад всередині своєї функції тривалості життя.
