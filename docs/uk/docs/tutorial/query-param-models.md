# Моделі параметрів запиту { #query-parameter-models }

Якщо у Вас є група **параметрів запиту**, які пов’язані між собою, Ви можете створити **Pydantic-модель** для їх оголошення.

Це дозволить Вам **повторно використовувати модель** у **різних місцях**, а також оголошувати перевірки та метадані для всіх параметрів одночасно. 😎

/// note | Примітка

Ця можливість підтримується, починаючи з версії FastAPI `0.115.0`. 🤓

///

## Заборона зайвих параметрів запиту { #forbid-extra-query-parameters }

У деяких особливих випадках (ймовірно, не дуже поширених) Ви можете захотіти **обмежити** параметри запиту, які дозволено отримувати.

Ви можете використати конфігурацію моделі Pydantic, щоб заборонити (`forbid`) будь-які зайві (`extra`) поля:

{* ../../docs_src/query_param_models/tutorial002_an_py310.py hl[10] *}

Якщо клієнт спробує надіслати **зайві** дані у **параметрах запиту**, він отримає **відповідь з помилкою**.

Наприклад, якщо клієнт спробує надіслати параметр запиту `tool` зі значенням `plumbus`, як у цьому запиті:

```http
https://example.com/items/?limit=10&tool=plumbus
```

Він отримає відповідь з **помилкою**, яка повідомить, що параметр запиту `tool` не дозволено:

```json
{
    "detail": [
        {
            "type": "extra_forbidden",
            "loc": ["query", "tool"],
            "msg": "Extra inputs are not permitted",
            "input": "plumbus"
        }
    ]
}
```

## Поєднання моделей параметрів { #combine-parameter-models }

Ви можете оголосити кілька моделей параметрів запиту та поєднати їх з окремими параметрами запиту або залежностями.

{* ../../docs_src/query_param_models/tutorial003_an_py310.py hl[9:15,20:22] *}

Параметри запиту залишаються на одному рівні.

```http
https://example.com/items/?limit=5&offset=10&tags=red&tags=blue&search=shirt
```

У строці запиту немає ключів `pagination` або `filters`. Кожна модель перевіряє параметри запиту незалежно, зі своїми значеннями за замовчуванням, валідаторами полів і валідаторами моделі. Те саме стосується моделей або окремих параметрів, оголошених у залежностях.

Якщо моделі мають спільне ім’я або псевдонім параметра, кожна модель перевіряє цей параметр запиту незалежно. Використовуйте різні імена або псевдоніми для незалежних значень. OpenAPI перелічує спільний параметр один раз, як і для параметрів, спільних із залежностями, тому спільні оголошення мають описувати однаковий тип і обмеження.

Конфігурація `extra` кожної моделі застосовується до всіх параметрів запиту, зокрема оголошених в інших моделях або залежностях. З `extra="forbid"` будь-який параметр поза цією моделлю відхиляється. З `extra="allow"` ці параметри включаються як додаткові дані моделі.

Це також працює для моделей `Header` і `Cookie`.

## Необов’язкові моделі параметрів запиту { #optional-query-parameter-models }

Оголосіть модель параметрів запиту з `| None` і значенням за замовчуванням `None`, щоб зробити групу необов’язковою.

{* ../../docs_src/query_param_models/tutorial004_an_py310.py hl[18] *}

Якщо не надіслано ні `start`, ні `end`, значення `date_range` буде `None`. Якщо надіслано будь-який із них, FastAPI перевіряє модель і вимагає обидва поля.

Використання `| None` без значення за замовчуванням залишає параметр обов’язковим.

Додаткові параметри обробляються відповідно до конфігурації `extra` моделі. Ігноровані додаткові параметри не роблять модель присутньою.

OpenAPI перелічує поля групи окремо та позначає їх як необов’язкові.

Ви також можете оголосити необов’язкові [моделі параметрів заголовків](header-param-models.md#optional-header-parameter-models) і [моделі параметрів кукі](cookie-param-models.md#optional-cookie-parameter-models).
