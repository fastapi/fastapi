# Моделі параметрів заголовків { #header-parameter-models }

Якщо у вас є група пов’язаних **параметрів заголовків**, ви можете створити **Pydantic модель** для їх оголошення.

Це дозволить вам повторно **використовувати модель** в **різних місцях**, а також оголосити валідації та метадані для всіх параметрів одночасно. 😎

/// note | Примітка

Ця можливість підтримується починаючи з версії FastAPI `0.115.0`. 🤓

///

## Заборонити додаткові заголовки { #forbid-extra-headers }

У деяких особливих випадках (ймовірно, не дуже поширених) ви можете захотіти **обмежити** заголовки, які хочете отримати.

Ви можете використати конфігурацію моделі Pydantic, щоб заборонити (`forbid`) будь-які додаткові (`extra`) поля:

{* ../../docs_src/header_param_models/tutorial002.py hl[10] *}

Якщо клієнт спробує надіслати **додаткові заголовки**, він отримає **помилку** у відповіді.

Наприклад, якщо клієнт спробує надіслати заголовок `tool` зі значенням `plumbus`, він отримає **помилку** у відповіді з повідомленням про те, що параметр заголовка `tool` не дозволений:

```json
{
    "detail": [
        {
            "type": "extra_forbidden",
            "loc": ["header", "tool"],
            "msg": "Extra inputs are not permitted",
            "input": "plumbus",
        }
    ]
}
```

## Вимкнути перетворення підкреслень { #disable-convert-underscores }

Так само, як і зі звичайними параметрами заголовків, коли у назвах параметрів є символи підкреслення, вони **автоматично перетворюються на дефіси**.

Наприклад, якщо у коді у вас є параметр заголовка `save_data`, очікуваний HTTP-заголовок буде `save-data`, і він так само відображатиметься в документації.

Якщо з якоїсь причини вам потрібно вимкнути це автоматичне перетворення, ви також можете зробити це для Pydantic моделей для параметрів заголовків.

## Поєднати моделі параметрів { #combine-parameter-models }

Ви можете поєднувати кілька моделей параметрів заголовків з окремими параметрами заголовків і залежностями. Кожна модель витягується та перевіряється незалежно, як пояснено для [моделей параметрів запиту](query-param-models.md#combine-parameter-models).

Конфігурація `extra` кожної моделі застосовується до всіх параметрів заголовків, включно з тими, що оголошені в інших моделях або залежностях. З `extra="forbid"` будь-який заголовок поза цією моделлю відхиляється. З `extra="allow"` ці заголовки включаються як додаткові поля моделі.

Кожна модель використовує власне налаштування `Header(convert_underscores=...)` як під час читання запиту, так і під час генерування OpenAPI. Явно задані псевдоніми полів залишаються буквальними назвами заголовків.

## Необов’язкові моделі параметрів заголовків { #optional-header-parameter-models }

Оголосіть модель параметрів заголовків з `| None` і значенням за замовчуванням `None`, щоб зробити групу необов’язковою.

{* ../../docs_src/header_param_models/tutorial004.py hl[15] *}

Якщо не надіслано ані `x-client-name`, ані `x-client-version`, `client` має значення `None`. Якщо надіслано хоча б один із них, FastAPI перевіряє модель і вимагає обидва поля.

Для значень за замовчуванням, додаткових полів і OpenAPI діють ті самі правила, що й для [необов’язкових моделей параметрів запиту](query-param-models.md#optional-query-parameter-models).

Заголовки на кшталт `Host` також підпорядковуються конфігурації `extra` моделі. З `extra="allow"` вони роблять модель присутньою, навіть якщо жодне з оголошених полів не передано.
