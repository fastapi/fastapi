# OpenTelemetry { #opentelemetry }

Когда ваш API запущен, вам может понадобиться узнать, сколько трафика он получает, какие HTTP-запросы выполняются медленно и когда возникают ошибки.

**Телеметрия** — это данные о поведении вашего приложения, которые помогают ответить на эти вопросы. К распространенным типам относятся:

- **Метрики**: измерения, которые можно агрегировать во времени, например время ответа и количество обрабатываемых HTTP-запросов.
- **Трейсы**: записи отдельных HTTP-запросов и операций, выполненных для их обработки. Каждая операция с измерением времени называется **span**.
- **Логи**: записи событий с временными метками, например запуск приложения или сбой операции.

[**OpenTelemetry**](https://opentelemetry.io/) — это набор стандартов и инструментов для сбора телеметрии и отправки ее в сервис мониторинга, где вы можете изучать ее на панелях мониторинга.

**FastAPI по умолчанию предоставляет поддержку OpenTelemetry** для трейсов, метрик и логов HTTP-запросов. WebSocket-соединения также предоставляют трейсы и логи. Чтобы увидеть эти данные, настройте сервис мониторинга для их получения.

## Другие сервисы мониторинга { #other-monitoring-services }

Чтобы отправлять телеметрию в другой сервис мониторинга, настройте endpoint, принимающий **OTLP** — протокол OpenTelemetry для отправки телеметрии. Используйте базовый HTTP/protobuf endpoint сервиса.

Установите эти переменные окружения, заменив пример URL на ваш endpoint:

```bash
export OTEL_SERVICE_NAME=my-api
export OTEL_EXPORTER_OTLP_ENDPOINT=https://collector.example.com
```

`OTEL_SERVICE_NAME` идентифицирует ваше приложение в сервисе мониторинга. Endpoint — это базовый URL для получения данных. Трейсы отправляются в `/v1/traces`, метрики — в `/v1/metrics`, а логи — в `/v1/logs` по этому URL.

Если вашему сервису требуется аутентификация, задайте `OTEL_EXPORTER_OTLP_HEADERS` со значением HTTP-заголовков, которые он указывает, например `api-key=YOUR_API_KEY`.

## Настройка телеметрии { #customize-telemetry }

### Настройка провайдеров и экспортеров { #configure-providers-and-exporters }

**Провайдер** предоставляет объекты, которые записывают трейсы, метрики или логи. Его конфигурация управляет тем, как эти данные обрабатываются и экспортируются.

Библиотеки телеметрии могут настраивать глобальные провайдеры OpenTelemetry. Настройте библиотеку до запуска приложения, и FastAPI будет автоматически использовать эти провайдеры.

Когда OTLP endpoint задан в окружении, FastAPI добавляет экспортер для этого назначения к каждому включенному провайдеру. Существующие экспортеры продолжают отправлять данные в свои назначения.

Настраивайте каждое назначение один раз. Если другая библиотека уже обрабатывает назначение из окружения, отключите для нее экспорт из окружения или выключите автоматическую настройку FastAPI:

```python
app = FastAPI(telemetry={"auto_configure": False})
```

Вы также можете передать провайдер напрямую в словаре `telemetry`. Например, этот провайдер использует консольный экспортер OpenTelemetry, чтобы выводить span HTTP-запросов в вашем терминале:

{* ../../docs_src/opentelemetry/tutorial002_py310.py hl[2:8] *}

**Экспортер** отправляет span в их назначение. `BatchSpanProcessor` группирует span и отправляет их в фоновом режиме. Замените консольный экспортер на экспортер, предоставленный вашей библиотекой мониторинга, чтобы использовать ее назначение. См. [руководство по инструментированию Python в OpenTelemetry](https://opentelemetry.io/docs/languages/python/instrumentation/) для дополнительных вариантов настройки.

Используйте `meter_provider` или `logger_provider` в том же словаре, чтобы предоставить провайдер метрик или логов. Приложение или библиотека, создающая провайдер, управляет его завершением работы. FastAPI управляет компонентами экспорта, которые он добавляет.

### Трассировка операций HTTP-запроса { #trace-request-operations }

По умолчанию трейсы HTTP-запросов включают span для разрешения зависимостей, запуска вашей функции-обработчика пути, сериализации ответа и запуска каждой задачи в `BackgroundTasks` FastAPI. Эти span используют тот же провайдер и экспортеры.

Span фоновых задач остаются частью трейса HTTP-запроса. Они выполняются после завершения span HTTP-ответа, поэтому не увеличивают измеряемое время ответа.

### Трассировка WebSocket-соединений { #trace-websocket-connections }

Каждое WebSocket-соединение имеет span вроде `WS /ws/{room}`, охватывающий handler и очистку зависимостей. Он использует тех же провайдеров и настройки, включая `operation_spans` для разрешения зависимостей и выполнения endpoint.

Метрики HTTP-запросов охватывают только HTTP-запросы. Обычные отключения WebSocket с кодами `1000` или `1001` не создают логи ошибок.

### Проверка ошибок { #inspect-errors }

FastAPI записывает необработанные исключения как логи OpenTelemetry, связанные с трейсом HTTP-запроса или соединения. Логи ошибок записываются даже тогда, когда трейс не был выбран для выборки.

Логи исключений включают тип исключения, сообщение и stack trace. Сообщения и stack trace могут содержать чувствительную информацию. Используйте процессоры логов вашего провайдера, чтобы фильтровать или маскировать их, либо задайте `logs` равным `False`, чтобы отключить эти логи.

FastAPI также записывает ошибки валидации HTTP-запросов как warning-логи с маршрутом и количеством ошибок. Эти логи не включают некорректные входные данные.

## Выбор того, что записывать { #choose-what-to-record }

Словарь `telemetry` также принимает эти настройки:

| Настройка | Назначение | По умолчанию |
| --- | --- | --- |
| `tracing` | Записывать span HTTP-запросов и WebSocket-соединений | `True` |
| `metrics` | Записывать метрики HTTP-запросов | `True` |
| `logs` | Записывать ошибки валидации и необработанные исключения | `True` |
| `operation_spans` | Добавлять span для операций HTTP-запроса | `True` |
| `exclude` | Пропускать HTTP-запросы, когда функция, получающая ASGI scope, возвращает `True` | `None` |
| `auto_configure` | Добавлять экспортеры для endpoints, заданных в переменных окружения | `True` |

Например, чтобы собирать метрики, исключая проверки работоспособности:

```python
from fastapi import FastAPI

app = FastAPI(
    telemetry={
        "tracing": False,
        "exclude": lambda scope: scope["path"] == "/health",
    }
)
```

Задайте `auto_configure` равным `False`, когда ваше приложение само выполняет настройку провайдера, например внутри своей функции lifespan.
